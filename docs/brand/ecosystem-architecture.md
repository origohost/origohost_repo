# OrigoHOST — Ecosystem Architecture

## 1. Master Brand Model

> **One ecosystem. One master brand. Multiple expressions.**

OrigoHOST operates as a **Master-Brand-Led / Branded House** architecture.
All ecosystem entities, programs, events and initiatives sit under the OrigoHOST master brand.

```
                        ORIGOHOST
```

## 4. Brand Architecture Rules

### Rule 1 — Master Brand Priority
The OrigoHOST name and visual identity always take precedence over any entity name.
Ecosystem entities always appear as **sub-expressions**, never as competing brands.

### Rule 2 — Naming Convention
Entity naming follows the pattern: `Origo [Descriptor]`
- ✅ Origo Cloud, Origo Academy, Origo Community
- ❌ OrigoCloud (no space), ORIGO CLOUD (all caps separately)

### Rule 3 — Campus Chapters
```
OrigoHOST Chapter — [Institution Name]
or
OrigoHOST — [Institution Name] Chapter
```
A chapter is an OrigoHOST ecosystem structure, not an independent brand.

### Rule 4 — Programs and Series
Programs belong to the OrigoHOST brand. Individual series or episode names
are sub-expressions, not standalone brands.

Example:
- Program: **Knowledge Sharing Series (KSS2026)**
- Episode: **KSS2026 — Episode 03: Cybersecurity & Ethical Hacking Fundamentals**

### Rule 5 — Future Sub-Brands
A genuinely independent sub-brand should only be created when there is a clear strategic reason:
- Distinct audience
- Independent value proposition
- Sustained operating model
- Long-term identity
- Significant scale
- Strategic necessity

Otherwise the master brand remains dominant.

## 6. Community Model

OrigoHOST operates as an **open, participation-driven technology community**.
There is no organization-wide formal tiered membership hierarchy.

**Participation Pathways:**
- Events, Workshops, Hackathons, Meetups
- Training and knowledge-sharing
- Mentorship
- Volunteering, speaking, organizing
- Campus initiatives
- Open-source contribution

**Roles (contribution pathways, not membership tiers):**
- Volunteer
- Ambassador
- Mentor
- Speaker
- Chapter Leader
- Contributor

---

## 7. Participant Transformation Model

```
EXPLORE → LEARN → BUILD → COLLABORATE → SOLVE → COMMUNICATE → LEAD → INNOVATE → CONTRIBUTE
```

**Intended transformation:**
> Passive learner → Active builder → Collaborative problem-solver → Leader → Innovator → Contributor

This is a **developmental philosophy**, not a formal membership ladder.
